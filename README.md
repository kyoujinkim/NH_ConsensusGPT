# NH_ConsensusGPT

다수의 애널리스트 보고서에서 질문과 관련된 근거를 검색하고, 이를 종합해 **텍스트 컨센서스**를 생성하는 RAG 연구 프로젝트입니다. 2023년 「애널리스트 보고서, GPT로 한눈에 보기」 연구를 담고 있습니다.


## 연구 결과

2023년 LangChain 보고서는 금융 리서치 검색→근거 추출→인용 기반 답변의 구현 사례를 제시합니다. 검색된 10개 문서 조각의 **4,373토큰**을 근거 추출 프롬프트로 **1,631토큰**까지 줄였습니다. 표시 수치로 계산하면 **약 62.7% 감소**이며, 한 사례의 컨텍스트 압축량입니다.

보고서는 일부 유의미한 내용이 생략됐지만 전반적인 요약이 양호했다고 정성 평가합니다. 일반 프롬프트의 단순 요약과 달리 결론 도출 프롬프트는 질문에 맞는 구조와 출처 인용을 생성하는 예시를 보입니다. 다만 정답이 있는 테스트셋의 정확도·환각률·인용 정합성·비용/지연에 대한 통계적 비교는 제시하지 않습니다.

따라서 토큰 감소를 답변 정확도 향상과 동일하게 해석하지 않습니다. 금융 리서치 적용에서는 중요한 숫자와 반대 근거의 누락, 인용 내용과 답변의 일치 여부를 별도 평가하는 출발점으로 사용할 수 있습니다. 예시 질문·전망은 보고서 작성 당시의 사례입니다.

출처: [230427_LangChain.pdf](https://github.com/kyoujinkim/NH_ConsensusGPT/blob/master/230427_LangChain.pdf) — PDF 10, 11, 14, 15쪽 — 검색·근거 추출 표 3~4 및 프롬프트 비교.

## 배경과 방법

실적 추정치의 평균처럼 시장 의견도 요약할 수 있을까라는 질문에서 출발했습니다. 보고서 전체를 단순 요약하는 대신, 질문에 관련된 문서 조각을 검색하고 답변·출처를 구성합니다.

```text
애널리스트 PDF
  → PDF 텍스트·메타데이터 추출
  → 문서 분할·Hugging Face 임베딩
  → Chroma 벡터 DB
  → 질문 관련 근거 검색
  → 반복 요약·결합·텍스트 컨센서스·출처
```

기존 README는 당시 매주 약 1,170편의 보고서가 발간된다는 배경과 텍스트 컨센서스의 활용 가능성을 설명합니다. 이 수치는 당시 연구의 배경이며 현재 발간량 통계로 사용하지 않습니다. 자료는 `230427_LangChain.pdf`와 [이전 README](README.previous.md)에 보존했습니다.

## 파일 구성

| 경로 | 역할 |
|---|---|
| `ConsensusGPT.ipynb` | 전처리·검색·생성 연구 노트북 |
| `readPDF.py` | PDF와 문서 메타데이터 읽기 |
| `promptTemplate.py` | 질문·요약·결합 프롬프트 |
| `quoteChecker.py` | 인용 번호·출처 정리 |
| `package/`, `링크` | 과거 배포·설치 관련 자료 |

과거 애플리케이션 안내는 당시 배포 기록입니다. 현재 설치 파일의 존재·지원 상태를 이 README에서 보장하지 않습니다.

## 환경·입력 준비

```bash
python -m pip install -r requirements.txt
```

requirements와 노트북은 이전 LangChain·OpenAI API 환경을 전제로 합니다. 최신 버전에서 그대로 동작한다고 가정하지 말고 호환 환경을 복원하거나 import·API를 함께 정리해야 합니다.

원래 노트북은 Google Colab과 Drive 사용을 가정하는 부분이 있습니다. 로컬에서 사용할 때는 Drive 마운트 부분과 PDF 경로를 변경합니다. `setting()`에 비공개 API 키·PDF 폴더·임베딩 모델·문서 분할 설정을 전달합니다. 실제 키를 노트북 셀·출력에 저장하지 마세요.

## 사용 흐름

1. 노트북의 import·환경 설정 셀을 준비합니다. 초기 설치 셀에는 과거 명령과 오타가 있을 수 있으므로 환경 파일과 함께 확인합니다.
2. `setting(...)`으로 PDF 자료를 읽고 `ChromaDB/` 검색 DB를 구성하거나 불러옵니다.
3. `run_proc(...)`에 `query`, `baseDocument`, 모델·근거 문서 수·반복 횟수 등의 설정을 전달합니다.
4. 생성된 답변과 인용 원문을 비교합니다.

`ChromaDB/`가 존재하면 재사용하는 분기가 있습니다. 문서·임베딩 모델·분할 규칙을 바꿨다면 기존 DB와 같은 실험인지 확인해야 합니다.

## 활용·한계

시장 전망의 공통 논거·이견·업종별 리스크를 빠르게 탐색하는 데 활용할 수 있습니다. 검색된 문서 수는 애널리스트 전체 의견의 대표성을 보장하지 않으며, 답변 문장이 실제 출처의 뉘앙스를 보존하는지도 확인해야 합니다.

자료에 없는 내용은 답변을 제한하는 것이 바람직합니다. 검색 결과가 적거나 충돌하는 경우 억지로 단일 결론을 만들지 말고 자료 공백과 이견을 드러내야 합니다. PDF·DB·생성 결과의 재배포 및 외부 모델 전송 권한은 별도로 확인하세요.
